# Evidence and explanations

## A compact evidence ledger

Use [claims.csv](../assets/templates/claims.csv) or the project's existing ledger. Each consequential claim needs an ID, exact proposition, source and version/date, page/table/section or timestamp, population and conditions, supported interpretation, and intended scenes. Keep an uncertainty or verification status.

Distinguish:

- Source-reported findings.
- Your reproduction or demonstration.
- Your interpretation of a source.
- Constructed teaching examples.
- Unresolved or contested assertions.

Do not put private source URLs or raw correspondence into public deliverables. Use an appropriate public citation, or describe the limitation without exposing the private material.

## Read beyond the headline

For research, inspect the actual method, figure caption, table footnotes, limitations, and source version. A benchmark name does not establish what was measured. A literature survey is evidence gathering; the lesson outline still follows learning questions.

For numerical comparisons, check denominator, filter, units, scoring direction, aggregation, uncertainty, baseline, sample size, and whether conditions are comparable. Recompute a derived value from the cited inputs. Mark unavailable results as unavailable rather than treating them as zero.

Common mistakes that a teaching agent should catch:

| Attractive shortcut | Required correction |
|---|---|
| “100% correct” in a preselected subset | Explain the inclusion filter; it is not population accuracy. |
| “This causes that” after a correlation | State the observed relationship and causal uncertainty. |
| “The average improved” | Explain what was averaged and which cases or subgroups changed. |
| “Faster response” | Define the measured start and endpoint: first output, useful output, or completed work. |
| “Best model/method” | Name the task, conditions, metric, and scope of the comparison. |
| “0.73 means 73% accurate” | Preserve the metric's actual meaning; an arbitrary score is not accuracy. |
| A paper about evidence selection proves evaluator reliability | Explain the source's actual task and label any broader analogy as interpretation. |

Do not automatically rescale every metric to 0–100. If a rescaling helps, show the transformation, preserve units/meaning, and avoid implying probability or school grades.

## Make the measurement teachable

Before showing a score, explain a concrete input, the behavior being measured, and the rule used to score it. Separate the actor being evaluated, the environment or interlocutor, and the judge. These can be three different entities.

For a timeline, specify whose event each marker represents. For a decision, specify what information the actor has then, including what is unavailable. Do not accidentally explain a causal system using future information.

Give the audience a small worked example before a large results table. If the user asks not to read numbers aloud, keep essential conditions and the supported takeaway in speech while retaining traceable visual values where appropriate.

## References and rights

Prefer primary sources for technical claims. Use visible short citations and a full bibliography or linked source list. Cite the version actually used, particularly when later versions change tasks or conclusions. Verify time-sensitive facts close to delivery.

A source being accessible does not automatically license copying its figure, audio, or full transcript. Prefer an original explanatory diagram with attribution where appropriate; obtain permission or use licensed excerpts for assets that need it. Keep asset provenance separate from claim provenance.

If source access fails, label the affected claim unverified and narrow or omit it. Do not invent page numbers, citations, results, or pretend an abstract was a full-paper read.

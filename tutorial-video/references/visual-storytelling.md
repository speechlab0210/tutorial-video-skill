# Visual storytelling

## Choose the representation by the relationship

| Teaching relationship | Useful representation |
|---|---|
| Stages or causal mechanism | Labeled sequence or flow diagram |
| Concurrent actors and timing | Lanes on a shared time axis |
| Controlled contrast | Side-by-side examples with the changed variable marked |
| Composition, frequency, magnitude | Native chart with units and an honest scale |
| Independent rankings on unrelated criteria | Separate ordered lists or leaderboards |
| Spatial or physical change | Demonstration, diagram, or purposeful animation |
| Real software procedure | Actual interface capture with readable focus |
| Competing interpretations | Shared evidence plus clearly separated interpretations |

Avoid connecting categorical ranks with lines unless continuity or movement is genuinely the intended variable. Put a quantity on an axis whose orientation matches the explanation. Do not make the audience mentally rotate a “higher means more” argument.

## Progressive disclosure is an argument

Map each spoken beat to a visible target. Record the reveal/highlight event and the intended order. If four mini-diagrams represent four cases, give each its own explanatory beat when needed. A highlight should guide attention to the relevant evidence; it should not reveal a later conclusion early.

Preserve objects across steps so the audience can recognize what changed. Use movement to show a meaningful transition rather than merely to create activity. Check the cue after encoding; source animation settings do not prove the exported timing.

For ambiguous interaction diagrams, label roles and actions explicitly: “customer asks,” “clerk checks availability,” “reviewer scores the answer.” A mysterious arrow between two boxes is rarely sufficient. If repeated text patches still leave the picture unclear, rebuild the example as a short illustrated sequence.

## Editable where it matters

Keep quantitative charts, tables, labels, formulas, and text editable when the user needs future revisions. An attractive screenshot of a chart does not satisfy a native-editability requirement. Open the final deck in its target application, change or inspect a representative object, and verify save/reopen behavior when relevant.

Use generated imagery for illustration, not as the sole renderer of exact labels, tables, or numbers. Composite precise text as native objects if necessary. For scientific figures, use plotting tools and preserve data and code.

A statement that “we ran this experiment” needs the actual result or demonstrable capture. An illustrative interface mockup can explain a concept, but must not be presented as evidence of a real run.

## A coherent design system

Record a compact palette, typography, category colors, component rules, and caption-safe area. Reuse the same category color across the entire course. Colors are project choices, not universal meanings. Pair color with labels or shape differences for accessibility. Check text and essential graphics against their background in final viewing conditions (projector, compression); WCAG's 4.5:1 for normal text and 3:1 for large text is a useful reference, not a substitute for viewing the export.

Choose font sizes by final viewing conditions. Pixel sizes, slide points, and embedded image dimensions are different units; a fixed number is not a universal readability guarantee. Inspect at realistic laptop/projector/mobile sizes. Enlarge the actual figure instead of filling unused space with decoration.

Provide useful alternative descriptions in accompanying materials where supported. Verbally describe the relationship that matters rather than relying on “as you can see.”

## Inspect the real export

Render and inspect every final slide, with particular attention to clipped bottom lines, missing glyphs, tiny citations, low-contrast text, stale labels, altered master backgrounds, distorted aspect ratios, and captions covering content. A contact sheet locates issues; it is not enough for small text.

Check consequential build states and embedded media in the actual presentation player. Native playback, PDF export, and the course video can behave differently. Keep untouched slides verifiably unchanged during a scoped revision.
